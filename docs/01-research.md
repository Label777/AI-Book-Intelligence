# Этап 1. Исследование продукта и конкурентов

Дата исследования: 15 ноября 2026 г. Цены и объёмы каталогов меняются часто — перед запуском их нужно перепроверить на официальных сайтах. Все цифры ниже снабжены ссылкой на источник; там, где источники расходятся, это отмечено явно.

## 1. Карта рынка

Рынок делится на два лагеря ([обзор Summio](https://summio-landing.pages.dev/best/ai-book-summary-apps)):

1. **Редакторские каталоги** — Blinkist, Headway, Shortform. Саммари пишут люди, каталог ограничен, качество предсказуемое.
2. **AI-инструменты «с открытым входом»** — пользователь сам указывает книгу или загружает файл (Summio, 3MinTop, MindMap AI, BeFreed, NotebookLM). Охват неограничен, но качество и достоверность сильно плавают.

AI Book Intelligence относится ко второму лагерю, но целится в глубину первого.

**Расхождения в источниках, которые нужно учитывать:**

- *Размер каталога Shortform.* Сам Shortform заявляет 10 000+ гайдов (против 9 000+ у Blinkist и 1 700+ у Headway), а [Nibble](https://nibble-app.com/blog/headway-alternatives) оценивает его примерно в 1 000 книг. Вероятно, первая цифра включает статьи и подкасты. Обе оценки исходят от заинтересованных сторон.
- *Месячный тариф Blinkist.* Shortform пишет, что месячного плана нет; BeFreed называет $15.99/мес. Цены зависят от региона и акций.
- Почти все сравнительные обзоры написаны самими участниками рынка (Shortform, Headway, Nibble, BeFreed, MindMap AI), поэтому оценки «кто лучше» в них ненадёжны. Мы используем из них только проверяемые факты.

## 3. Что из этого следует

**Незанятая ниша.** Никто не объединяет четыре вещи сразу:

1. любая книга (как AI-инструменты);
2. глубина и критика (как Shortform);
3. привязка каждого утверждения к источнику (как NotebookLM);
4. визуальная подача в формате презентации (как Gamma).

**Главный риск категории — доверие.** Независимые тесты саммаризаторов сводятся к вопросу, каким саммари вообще можно верить ([MindMap AI](https://mindmapai.app/blog/153/best-ai-book-summarizers)), а гайды по выбору ставят привязку к источнику в число ключевых критериев наряду с охватом, управлением глубиной и ценой ([Summio](https://summio-landing.pages.dev/how-to/choose-a-book-summary-app)). Даже про NotebookLM отмечают, что гладкий слайд или аудиообзор может содержать неверную интерпретацию ([plus2net](https://mail.plus2net.com/articles/ai-notebookLM.php)).

Отсюда позиционирование:

> **AI Book Intelligence — аналитический разбор любой книги, в котором видно, откуда взято каждое утверждение.**

Отличия, которые нужно защищать в продукте:

- **Четыре типа утверждений** на каждом слайде: факт из книги, интерпретация AI, внешнее исследование, критический вывод.
- **Два режима анализа:** по полному тексту (файл пользователя) и по открытым источникам. Режим всегда виден пользователю.
- **Никаких выдуманных глав и цитат** — если оглавления нет в надёжных источниках, слайд честно перестраивается в тематический разбор.
- **Глубина по запросу:** обзор → разбор → Deep Dive по одной идее. Фиксированная длина саммари — общая слабость каталогов.
- **Действие, а не только чтение:** план на 24 часа / 7 дней / 30 дней, тест, карточки.

**Что сознательно не делаем в первой версии:** геймификацию в стиле Headway, собственное мобильное приложение (достаточно адаптивного веба), генерацию видео.

## 5. Источники данных о книгах

**Open Library** — основной источник метаданных: поиск по названию, автору и ISBN, произведения и издания, обложки, API без ключа ([документация](https://openlibrary.org/developers/api)). Ограничения, влияющие на архитектуру:

- анонимно — 1 запрос в секунду; с заголовком `User-Agent`, где указаны название приложения и контакт, — 3 запроса в секунду ([история правок документации](https://openlibrary.org/developers/api?b=102&m=diff));
- сервис просит не использовать API как бэкенд высоконагруженных сервисов и не выкачивать данные массово.

Вывод: все ответы Open Library кэшируются в нашей базе, поиск идёт через наш сервер с очередью и ограничителем частоты. Данные ведёт сообщество, поэтому записи бывают неполными, а имена авторов — в разных формах ([разбор на dev.to](https://dev.to/devil_scrapes/open-library-scraper-the-goodreads-api-alternative-youve-been-missing-17em)) — нужна нормализация.

**Запасные источники:** Google Books API (описания, иногда оглавления; квоты проверить на этапе 5), Wikidata и Википедия (год первой публикации, жанр, контекст).

**Содержание книги без полного текста** собирается из: издательского описания, оглавления (если опубликовано), статей энциклопедий, рецензий, интервью автора. Этого достаточно для обзора идей и критики, но недостаточно для достоверного пересказа каждой главы — поэтому разбор по главам в этом режиме строится только на подтверждённом оглавлении.

## 6. Возможности AI API

Для этапов генерации выбран Claude API (обоснование — в [архитектуре](03-architecture.md)). Что важно для проекта:

- **Веб-поиск как серверный инструмент.** Модель сама решает, когда искать, поиск может повторяться несколько раз за запрос, ответ приходит со ссылками на источники; число поисков ограничивается параметром `max_uses`, есть списки разрешённых и запрещённых доменов ([документация](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)). Если результаты показываются конечным пользователям, ссылки на источники должны быть видимыми и кликабельными — это совпадает с нашим требованием прозрачности.
- **Структурированные ответы.** Вывод можно ограничить JSON-схемой, а входы инструментов — строгой схемой ([обзор в блоге Microsoft Foundry](https://devblogs.microsoft.com/foundry/?p=2848)). Это основа формата слайдов.
- **Цитирование собственных документов.** Блоки `search_result` и документы с включённым цитированием возвращают ссылки на конкретные фрагменты ([документация](https://platform.claude.com/docs/en/build-with-claude/search-results)). Используем для анализа по загруженному файлу и для чата по книге.
- **Ограничение:** при запросе «только JSON» цитат в ответе может почти не быть; для структурированных данных с цитатой на каждое значение у Anthropic есть отдельный рецепт (та же страница документации). Поэтому в пайплайне шаг «извлечь утверждения со ссылками» отделён от шага «собрать слайды в JSON». Точную схему вызовов нужно проверить на этапе 6.
- **Пакетная обработка и кэширование промптов** работают вместе с веб-поиском ([документация по веб-поиску](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)) — это снижает стоимость фоновой генерации и повторных вызовов с одним и тем же текстом книги.

## 7. Авторское право

Это не юридическая консультация; перед коммерческим запуском нужен юрист. Принципы, заложенные в продукт:

- анализ — оригинальный текст, а не пересказ, близкий к оригиналу;
- дословные цитаты — короткие, с лимитом на книгу, только при точном совпадении с источником;
- загруженные файлы приватны, не попадают в общий кэш и не используются для других пользователей;
- анализы, построенные на загруженном тексте, видны только владельцу файла;
- есть контакт и процедура для обращений правообладателей.

## 8. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Выдуманные детали при отсутствии текста | Высокая | Типы утверждений, проверка фактов отдельным шагом, отказ от разбора глав без оглавления |
| Не та книга или не то издание | Средняя | Обязательное подтверждение издания пользователем |
| Стоимость генерации | Средняя | Кэш по произведению, разные модели для разных шагов, пакетная обработка, лимиты |
| Малоизвестные книги без источников | Высокая | Честный отчёт о покрытии: «источников мало — загрузите файл» |
| Претензии правообладателей | Низкая–средняя | Раздел 7 |
| Текст книги или веб-страница содержит инструкции для модели | Средняя | Контент источников передаётся как данные, вывод ограничен схемой |
| Ограничения Open Library | Средняя | Кэш, очередь, запасные источники |
