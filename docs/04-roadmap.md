## Этап 4. Главная страница

**Зависимости:** подтверждённый стек; возможность устанавливать пакеты.

**Задачи**

1. Инициализировать проект: Next.js, TypeScript, Tailwind, линтер, форматирование, Vitest, Playwright, проверки в GitHub Actions.
2. Перенести дизайн-токены в конфигурацию; тёмная тема по умолчанию, светлая — по переключателю, выбор сохраняется.
3. Базовые компоненты: кнопка, поле, карточка книги, метка происхождения, заглушки загрузки.
4. Визуальные макеты главной и презентации.
5. Главная: заголовок, поле поиска, «как это работает», блок о работе с источниками.
6. Блоки «Примеры», «Популярные книги», «Моя библиотека» подключаются по мере готовности данных (этапы 6 и 9) — до этого не показываются.

**Критерии готовности**

- Главная корректна на ширинах 360, 768, 1280 и 1920 px в обеих темах.
- Поле поиска ведёт на страницу результатов (сама выдача — этап 5).
- Контраст текста не ниже 4.5:1; вся страница проходится с клавиатуры.
- Нет элементов без функции.

**Тесты:** модульные для компонентов; сценарий Playwright со снимками экрана на четырёх ширинах.

**Итог:** этап выполнен, все критерии готовности проверены тестами. Подробности, решения и снимки экрана — в [отчёте по этапу](06-home-page.md).

## Этап 5. Поиск и идентификация книг

**Зависимости:** этап 4; база данных; контактный адрес для Open Library.

**Решения перед началом**

- **Кэш.** Этап начинается без базы данных: кэш ответов каталога живёт в памяти процесса и спрятан за интерфейсом хранилища. Когда появится проект Supabase, реализация заменяется на таблицу в Postgres без изменений в остальном коде. До этого кэш не переживает перезапуск сервера — для разработки этого достаточно.
- **Контакт для Open Library.** В заголовке `User-Agent` указывается название приложения и адрес репозитория. Личная почта владельца в код и запросы не попадает; при желании отдельный адрес задаётся переменной окружения `OPEN_LIBRARY_CONTACT`.
- **Загрузка файлов** (задачи 5 и 6) требует хранилища Supabase и делается после его подключения; поиск и подтверждение издания от него не зависят.

**Задачи**

1. Клиент Open Library с ограничителем частоты, повторами и кэшем в базе.
2. Нормализация: имена авторов, объединение изданий одного произведения, год первой публикации.
3. Ранжирование кандидатов и оценка уверенности; запасной поиск в Google Books.
4. Страницы результатов и подтверждения издания.
5. Загрузка файла: прямая отправка в хранилище, проверка типа и размера, извлечение метаданных, сопоставление с произведением.
6. Разбор EPUB, PDF, TXT на главы и фрагменты в фоновой задаче.

**Критерии готовности**

- Контрольный набор из 50 запросов (точные названия, опечатки, одноимённые книги, кириллица и латиница): нужная книга в первой тройке не реже чем в 90 % случаев.
- Повторный запрос не обращается к внешнему API.
- Файлы с DRM, сканы без текста и пустые файлы дают понятное сообщение.
- Чужой файл недоступен по прямой ссылке.

**Тесты:** модульные на нормализацию и ранжирование по записанным ответам API; сценарные на поиск и загрузку.

## Этап 6. AI-движок анализа

**Зависимости:** этап 5; ключ Claude API; сервис очередей.

**Задачи**

1. Схемы данных: утверждение, источник, слайд, оценка.
2. Каркас пайплайна: шаги, сохранение результатов, повтор с места сбоя, учёт токенов и стоимости.
3. Шаги 1–8 по [архитектуре](03-architecture.md), по одному, каждый со своими тестами.
4. Программные проверки: точное совпадение цитат, поиск повторов, покрытие глав, лимиты длины.
5. Отчёт о покрытии источниками и порог запуска.
6. Поле «действие» у идей и инсайтов с программной проверкой конкретности.
7. Набор контрольных книг и скрипт регрессионной проверки.

**Критерии готовности**

- Полный прогон для книги в обоих режимах без ручного вмешательства.
- Сбой любого шага не теряет результаты предыдущих.
- На контрольном наборе: ни одной главы без подтверждённого оглавления, ни одной цитаты без точного совпадения, у каждого факта есть источник.
- Ручная проверка пяти анализов по книгам, содержание которых известно: фактических ошибок нет.
- Стоимость прогона измерена и записана.

## Этап 7. Интерактивная презентация

**Зависимости:** этап 6 (реальные данные), этап 4 (компоненты).

**Задачи**

1. Компоненты для всех шаблонов слайдов и шести типов схем.
2. Просмотрщик: навигатор, клавиатура, режимы «слайды» и «чтение», полный экран.
3. Метки происхождения и карточка источника.
4. Страница хода генерации с открытием слайдов по мере готовности.
5. Мобильная версия: вертикальные карточки, свайп, нижняя панель.
6. Модуль AI-аналитики: шесть оценок и четыре «самые…» идеи.

**Критерии готовности**

- Все 12 разделов ТЗ отображаются на реальных данных; длинный текст не ломает слайд.
- У каждого утверждения источник открывается в один клик.
- Презентация удобна на телефоне шириной 360 px.
- Режим анализа виден на каждом экране презентации.

## Этап 8. Дополнительные AI-инструменты

**Зависимости:** этап 7.

Порядок — по ценности и зависимости друг от друга:

1. Bookmark (нужен для плана и библиотеки).
2. AI Book Chat с поиском по утверждениям и фрагментам.
3. Explain Like I'm 5 и Deep Dive.
4. Quiz Mode и Flashcards с интервальным повторением.
5. Mind Map.
6. Personal Action Plan.
7. Listen Mode.
8. Compare Books и сравнение авторов по теме.
9. Интеллектуальный профиль (после появления учётных записей на этапе 9).

**Критерии готовности:** каждый инструмент работает на реальных данных, сохраняет состояние, доступен с телефона; чат честно отвечает «в источниках этого нет», когда ответа нет; вопросы теста проверяются по утверждениям типа «факт».

## Этап 9. Экспорт, авторизация и библиотека

**Зависимости:** этап 7; Supabase Auth.

**Задачи**

1. Вход по почте и через Google; защита на уровне строк для всех пользовательских таблиц.
2. Библиотека: сохранённые анализы, прогресс, закладки, планы.
3. Печатный маршрут и сервис экспорта в PDF; кэш готовых файлов.
4. Перенос данных гостя в аккаунт после регистрации.
5. Удаление аккаунта и данных.

**Критерии готовности:** PDF совпадает с экраном в обеих темах и содержит метки происхождения и список источников; данные одного пользователя недоступны другому (проверено тестом); блоки «Моя библиотека» и «Популярные книги» на главной работают.

## Этап 10. Тестирование, оптимизация и запуск

**Задачи**

1. Полный сценарный прогон на десктопе и телефоне.
2. Производительность: время загрузки главной и презентации, размер кода.
3. Проверка доступности.
4. Нагрузочная проверка очереди и лимитов.
5. Оптимизация стоимости: выбор моделей по шагам, пакетная обработка, кэш промптов.
6. Мониторинг ошибок и расходов; бюджетные оповещения.
7. Юридические страницы, процедура для правообладателей.
8. Наполнение: 10–20 готовых анализов для блока «Примеры».
9. Перепроверка цен и возможностей конкурентов из [исследования](01-research.md).

**Критерии готовности:** все сценарии проходят; нет кнопок без функции; расходы на один анализ укладываются в установленный бюджет; документация соответствует коду.
