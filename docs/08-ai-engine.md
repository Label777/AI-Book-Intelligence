| Контрольный набор: нет неподтверждённых глав, нет цитат без совпадения, у каждого факта источник | Правила реализованы в коде и проверены тестами; прогон на контрольных книгах — после получения ключа |
| Ручная проверка пяти анализов | Не выполнена |
| Стоимость прогона измерена | Не выполнена; учёт токенов и поисков по шагам готов |

## Что сделано

```

  schema.ts        схемы: книга, источник, утверждение, действие, схема, содержание, слайд
  config.ts        лимиты, пороги, выбор моделей по уровням
  runner.ts        каркас: шаги по очереди, сохранение, повтор с места сбоя, учёт расхода
  store.ts         хранилище шагов: интерфейс и реализация в памяти
  file-store.ts    хранилище шагов в файлах — для контрольных прогонов
  model.ts         интерфейс модели, учёт токенов, расчёт стоимости по тарифу
  anthropic.ts     клиент Claude API: ответы по схеме и веб-поиск
  claims.ts        реестр утверждений: постоянные идентификаторы, ссылки между утверждениями
  prune.ts         удаление неподтверждённого вместе со всем, что на нём держалось
  text.ts          нормализация и похожесть текстов

  steps/           восемь шагов
```

### Шаги

| № | Шаг | Что делает | Модель |
|---|---|---|---|
| 1 | `identify` | Проверяет подтверждённую книгу, отклоняет неподдерживаемый режим | — |
| 2 | `sources` | Веб-поиск сведений о книге; определение вида источников; оглавление; отчёт о покрытии | основная, 2 вызова |
| 3 | `structure` | Главы — если оглавление подтверждено; иначе темы, каждая с опорой на выдержку | основная, 0–1 вызов |
| 4 | `summary` | Факты по главам или темам и обзор книги | основная |
| 5 | `analysis` | Идеи, инсайты, концепции, мировоззрение автора, критика, связи, выводы, оценки | сильная и основная, 8 вызовов |
| 6 | `visuals` | Схема для каждой концепции: один из шести типов | основная |
| 7 | `assemble` | Сборка 14–20 слайдов | — |
| 8 | `verify` | Независимая проверка каждого факта по его выдержкам; удаление, понижение, пересборка | сильная, по 12 утверждений на вызов |

Вызовы внутри шага 5 идут последовательно: каждый следующий получает уже сформулированные мысли, чтобы не повторять их.

### Как обеспечена достоверность

- **Выдержки пишет не модель.** При веб-поиске API возвращает дословные фрагменты найденных страниц. Они сохраняются как выдержки источников, и все проверки фактов и цитат идут по ним.
- **Факт без выдержки не принимается.** Утверждение типа «Книга» или «Исследование» обязано ссылаться на конкретную выдержку существующего источника; «Исследование» — на источник за пределами самой книги.
- **Вывод без оснований не принимается.** Интерпретация и критика обязаны ссылаться на утверждения, из которых следуют.
- **Цитата — только при точном совпадении.** Сверяется код, а не модель. Несовпавшая цитата снимается. Длинный фрагмент в кавычках прямо в тексте тоже считается цитатой; если его нет в источнике, утверждение отклоняется.
- **Главы не придумываются.** Оглавление принимается, если оно совпало в двух источниках с разных сайтов, и каждое название главы действительно есть в выдержке. Иначе разбор идёт по темам с пометкой, что темы выделены AI.
- **Проверка фактов отдельным вызовом.** Проверяющий видит только утверждение и его выдержки и не знает, как оно было получено. «Не подтверждено» и отсутствие вердикта — удаление; «подтверждено частично» — понижение до интерпретации AI.
- **Каскад.** Вместе с удалённым фактом уходят выводы, потерявшие все основания, а с ними идеи, действия, оценки и выделения, которые на них держались.
- **Действие должно быть шагом.** У действия обязательны объект и условие; формулировки вроде «старайтесь», «важно помнить» отклоняются.
- **Повторы.** Близкие формулировки находит сравнение по триграммам символов. Пересказ другими словами код не видит — здесь защита только в промпте: модель получает список уже высказанных мыслей.
- **Замечания возвращаются модели.** Если ответ не прошёл проверки, модель получает их список и отвечает заново, до трёх попыток. Затем негодные элементы отбрасываются.
- **Лучше пустой раздел, чем выдуманный.** Необязательный раздел, который не удалось построить на фактах, остаётся пустым и попадает в отчёт; слайд для него не создаётся.
- **Анализ не публикуется**, если после проверки осталось меньше трёх идей, меньше восьми слайдов или нет обзора книги.

Тексты источников передаются модели в тегах как данные, с указанием не выполнять содержащиеся в них инструкции.

### Результат

Шаг 8 возвращает то, из чего этап 7 строит презентацию:

| Поле | Содержание |
|---|---|
| `claims` | Утверждения: тип, текст, источники, основания, цитата, результат проверки |
| `content` | Разделы анализа; ссылаются на утверждения по идентификаторам |
| `slides` | Слайды: раздел, шаблон, заголовок, блоки |

Источники с выдержками — в результате шага 2. Виды блоков слайда: `meta`, `claim`, `item`, `action`, `diagram`, `score`, `note`.

## Как запустить

Тесты на подставной модели входят в обычную проверку:

```bash
npm run check
```

Прогон на настоящей модели (тратит токены):

```bash
cp .env.example .env.local          # вписать ANTHROPIC_API_KEY
export $(grep -v '^#' .env.local | xargs)
npm run eval                        # первая книга из evals/books.json
EVAL_BOOKS=atomic-habits,sapiens npm run eval
```

Результаты шагов сохраняются в `evals/out/` (в репозиторий не попадают). Прерванный прогон продолжается с места остановки, повторный запуск без изменений ничего не тратит. В конце печатается таблица: статус, покрытие, отчёт проверки, расход токенов и число поисков.

## Решения и ограничения

1. **Числа из ТЗ — цель, а не обязанность.** ТЗ требует 10 инсайтов и 10 выводов, но запрещает повторять мысль ради объёма. При конфликте побеждает запрет: минимум — пять, сверх него только то, что прошло проверки.
2. **Схемы ответов без полей, допускающих null.** Структурированный вывод Claude API ограничивает число таких полей на запрос. В черновике утверждения отсутствие значения передаётся пустой строкой; тест следит, чтобы ни одна схема не превысила ограничение.
3. **Связанные книги не сверяются с каталогом.** Раздел «Связь с другими знаниями» называет другие книги; существование книги и автора пока проверяется только инструкцией в промпте. После этапа 5 их нужно сверять поиском по каталогу.
4. **Хранилище — в памяти и в файлах.** Интерфейс `PipelineStore` готов к реализации на Postgres. Фоновая очередь не подключена: каркас — обычная асинхронная функция, шаги которой переносятся в очередь один к одному.
5. **Кэш промптов и пакетная обработка не используются.** Это оптимизация стоимости; её стоит делать после первых замеров.
6. **Тарифы в код не зашиты.** `costOf` считает стоимость по тарифу, который передаёт вызывающий код.
7. **Интеллект-карта не строится.** Инструмент отнесён к версии 1.3; граф можно будет собрать из готового содержания без новых вызовов модели.
8. **Языки анализа — русский и английский.**

## Что дальше

1. Получить ключ Claude API и прогнать контрольные книги; по результатам править промпты.
2. Измерить время и стоимость прогона, записать их сюда.
3. Вручную проверить пять анализов по книгам с известным содержанием.
4. После этапа 5: принимать книгу из поиска и сверять связанные книги с каталогом.
5. Подключить хранилище в базе и фоновую очередь.
