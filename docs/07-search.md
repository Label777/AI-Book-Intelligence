# Этап 5. Поиск и идентификация книг

## Что сделано

| Задача из [плана](04-roadmap.md) | Результат |
|---|---|
| Клиент Open Library | `src/books/openlibrary/client.ts`: представляется по правилам каталога, не чаще трёх запросов в секунду, до двух повторов при сбое, тайм-аут 8 с, кэш на 30 дней |
| Нормализация | Имена авторов в естественном порядке и без повторов, объединение дублей одного произведения, год первой публикации из поискового индекса каталога |
| Ранжирование и уверенность | `src/books/rank.ts`: оценка по совпадению слов запроса с названием и автором (с поправкой на опечатки и разные алфавиты), популярности и порядку каталога; пересказы и конспекты опускаются |
| Запасные источники | Wikidata переводит название на английский, Google Books исправляет опечатки; данные о книге всё равно берутся из Open Library |
| Страницы | `/search` — результаты и все состояния; `/book/[workId]` — подтверждение книги и выбор издания |

Загрузка файлов и разбор EPUB, PDF, TXT (задачи 5–6) перенесены в версию 1.2 — так решено в [«Фокусе продукта и MVP»](05-focus-and-mvp.md).

## Как идёт поиск

1. **Запрос как есть.** Если первый результат — не пересказ и в нём буква в букву нашлись все слова запроса, поиск окончен. Так завершаются 42 из 50 контрольных запросов.
2. **Ослабленный запрос.** Каталог ищет все слова сразу, и одно слово с опечаткой прячет книгу. Поэтому слова убираются по одному, начиная с подозрительного, а из всего найденного выбирается лучшее совпадение с полным запросом. Пример: «outliers gladwel» → поиск «outliers» → «Outliers» Малкольма Гладуэлла.
3. **Перевод или исправление названия.** Если подходящей книги всё ещё нет, Wikidata ищет название на языке запроса и возвращает английское название и автора; если не нашла — то же пробует Google Books. Пример: «Атомные привычки» → «Atomic Habits James Clear».

Пользователь всегда видит, что произошло: «Точного совпадения нет. Показаны результаты по запросу …». После шагов 2 и 3 система не утверждает, что уверена в результате.

Готовый результат запоминается целиком, поэтому повторный поиск не обращается ни к одному внешнему сервису.

## Критерии готовности

| Критерий | Результат |
|---|---|
| Нужная книга в первой тройке не реже чем в 90 % из 50 контрольных запросов | **47 из 50 (94 %)** на настоящем каталоге — см. ниже |
| Повторный запрос не обращается к внешнему API | Проверено модульным и сценарным тестами |
| Сообщения о файлах с DRM, сканах, пустых файлах; чужой файл недоступен по ссылке | Относятся к загрузке файлов — версия 1.2 |

### Живая проверка на 50 запросах

Контрольный набор — `tests/eval/queries.ts`: точные названия, название с автором, опечатки, одноимённые книги, кириллица. Проверка идёт против настоящего Open Library в GitHub Actions (`.github/workflows/search-eval.yml`): запускается вручную и при изменении кода поиска, итог виден в аннотациях к запуску. Локально — `npm run eval:search`.

| Группа | В первой тройке |
|---|---|
| Точное название | 15 из 15 |
| Название и автор | 10 из 10 |
| Опечатки | 10 из 10 |
| Одноимённые книги | 5 из 5 |
| Кириллица | 7 из 10 |

Результат получен за три прохода: 82 % → 88 % → 94 %. Каждый проход показал конкретную причину промахов, которую нельзя было увидеть на записанных ответах: слово с опечаткой прячет книгу; при отправке в каталог «й» превращалась в «и»; для русского запроса каталог подставлял испанское название издания.

### Известные промахи

- **«Сапиенс Харари»** — название и автор кириллицей, а в каталоге книга записана латиницей. Запрос «Sapiens Harari» работает.
- **«Думай медленно, решай быстро»**, **«Богатый папа, бедный папа»** — русских изданий в Open Library нет, а Wikidata не нашла книгу по этому написанию.

Общая причина: Open Library слабо покрывает русские издания. Это ограничение источника; улучшить можно дополнительным каталогом с русскими изданиями — стоит вернуться к этому после MVP.

## Тесты

- **Модульные** (`tests/unit/books-*.test.ts`, `catalog-client.test.ts`, `wikidata.test.ts`): сравнение текста, разбор ответов, ранжирование, порядок шагов поиска, клиент, кэш, ограничитель частоты.
- **Сценарные** (`tests/e2e/search.spec.ts`): все состояния поиска и страницы книги на 360 и 1280 px в обеих темах, проверка доступности axe, работа кэша. Приложение в них обращается к локальной заглушке каталога (`tests/e2e/mock-catalog.mjs`).

Ответ о произведении в `tests/fixtures/openlibrary/` записан с настоящего каталога; ответы поиска и списка изданий составлены по документированному формату, потому что из среды разработки каталог недоступен. Соответствие настоящим ответам подтверждает живая проверка: она же проверяет страницу книги («Sapiens»: автор, год 2011, 86 изданий на 13 языках, обложка, описание).

## Принятые решения

1. **Нет автоматического перехода к книге.** В проекте интерфейса уверенное совпадение сразу открывало страницу подтверждения. На практике переход средствами Next.js срабатывал повторно при возврате к результатам. Теперь уверенное совпадение выделено сверху с кнопкой «Да, это она» — на один клик больше, зато видны остальные результаты и «назад» работает предсказуемо.
2. **Wikidata добавлена к запасным источникам.** В плане был только Google Books, но он не переводит названия, а без ключа ненадёжен.
3. **Выбор издания хранится в адресе страницы** (`?edition=…`): работает без JavaScript, переживает перезагрузку, ссылкой можно поделиться.
4. **Описание книги подписано как описание из каталога** — это текст Open Library, а не вывод AI.
5. **Обложка, которая не загрузилась, заменяется типографической.**
6. **Кэш в памяти процесса** за интерфейсом `CacheStore` (`src/lib/cache.ts`). До подключения базы он не переживает перезапуск сервера.
7. **Маршрутов API нет**: страницы вызывают функции поиска на сервере напрямую. Маршруты появятся, когда понадобятся клиентским функциям.

## Что дальше

Страница книги заканчивается сообщением, что запуск анализа появится на следующем этапе. AI-движок ([этап 6](08-ai-engine.md)) принимает книгу в том же виде, в каком её отдаёт поиск (`workId`, название, авторы, год, описание, темы), — соединить их предстоит на этапе 7.
