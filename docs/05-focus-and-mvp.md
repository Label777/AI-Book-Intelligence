# Фокус продукта и MVP

Этот документ уточняет ТЗ: что считать главным, какие три функции дают преимущество и что входит в первую версию.

## 1. Фокус: извлечение знаний, а не пересказ

Саммари доступно где угодно и стоит дёшево. Самостоятельную ценность имеет то, что сложно получить одним запросом к чат-боту:

| Слой | Вопрос пользователя | Где в продукте |
|---|---|---|
| Анализ | Что здесь главное и как это устроено? | Идеи, концепции, схемы |
| Критика | Чему здесь можно верить? | Критический анализ, AI-аналитика, метки происхождения |
| Связи | Как это соотносится с тем, что я уже знаю? | Связи с другими книгами, сравнение авторов, профиль |
| Действие | Что мне с этим делать? | Действие у каждой идеи, план внедрения |

Следствие для генерации: пересказ занимает не больше трети презентации. Слайды «О чём книга» и «Разбор по главам» — опора для остального, а не основное содержание.

## 2. Три функции-преимущества

### 2.1. «Что мне с этим делать»

Каждая главная идея и каждый инсайт получают обязательное поле **действие** — конкретный шаг, который можно выполнить, а не совет общего вида.

- Действие формулируется как глагол + объект + условие: «в конце рабочего дня записать три решения, принятых на автомате».
- Проверка при сборке: действие без конкретного объекта или срока отклоняется и генерируется заново.
- Слайды «Практическое применение» и «План внедрения» собираются из этих действий, а не пишутся отдельно — поэтому план всегда связан с идеями книги.
- После MVP: три вопроса о целях пользователя (сфера, задача, сколько времени готов уделять) — и план пересобирается под него.

Действие — это интерпретация AI, и помечается соответствующей меткой: автор книги этого шага не предлагал, если не сказано обратное.

### 2.2. Сравнение авторов

Расширение функции Compare Books: сравниваются не две книги, а подходы авторов к одной теме. Пример — взгляды Роберта Кийосаки и Моргана Хаузела на деньги.

**Вход:** два-три автора и тема (или только авторы — тогда темы предлагаются по пересечению их книг).

**Выход:**

1. Общие вопросы темы, на которые отвечают оба автора.
2. Позиция каждого по каждому вопросу.
3. Где они согласны.
4. Где расходятся — и из каких исходных посылок это расхождение следует.
5. Кому какой подход подходит.
6. Что взять у каждого — в виде действий.

**Правила достоверности:**

- Позиция автора берётся только из утверждений типа «Книга» с источником. Формулировка «автор считает» без источника запрещена.
- Сопоставление и вывод о причинах расхождений — интерпретация AI, с меткой.
- Сравниваются книги, а не люди: в заголовке всегда указано, по каким книгам построено сравнение. Если у автора разобрана одна книга, это видно.
- Если анализа нужной книги ещё нет, он запускается перед сравнением.

Функция опирается на хранилище утверждений из [архитектуры](03-architecture.md): сравнение — это запрос к уже проверенным данным, а не новая генерация с нуля.

### 2.3. Персональный интеллектуальный профиль

Система ведёт карту того, что пользователь изучил, и подсказывает, что дальше.

**Что показывает:**

- **Карта тем** — области, в которых пользователь изучал книги, и глубина по каждой.
- **Пробелы** — темы, смежные с изученными, но не затронутые.
- **Другая точка зрения** — если все изученные книги по теме стоят на одной позиции, профиль предлагает автора с противоположной.
- **Что дальше** — три-пять рекомендаций, у каждой объяснение: какой пробел она закрывает и с какой изученной книгой связана.

**Из чего считается глубина:** открытые анализы, пройденные тесты, повторённые карточки, сохранённые закладки, выполненные пункты плана.

**Честность формулировок:**

- «Изучено» означает «пользователь работал с материалом», а не «усвоил». Профиль так и говорит.
- Пробелы — рекомендация AI, а не объективное измерение знаний.
- Профиль приватный, его можно выгрузить и удалить.

Экран строится как панель показателей плюс граф знаний (см. визуальные референсы в [UX/UI](02-ux-ui.md)). Требует учётной записи и накопленной истории, поэтому появляется после MVP.

## 3. MVP: одна функция, сделанная идеально

**Вводишь название книги — получаешь презентацию из 14–20 слайдов с глубоким разбором.**

Всё, что не лежит на этом пути, откладывается.

### 3.1. Что входит

| Часть | Объём в MVP |
|---|---|
| Главная | Заголовок, поле поиска, примеры готовых презентаций; тёмная тема по умолчанию |
| Поиск | Open Library, подтверждение книги пользователем |
| Генерация | Все восемь шагов пайплайна в режиме «по открытым источникам» |
| Отчёт о покрытии | Показывается до запуска; при нехватке источников — честный отказ или сокращённый обзор |
| Презентация | Просмотрщик, метки происхождения, список источников, клавиатура, телефон |
| Действия | Поле «действие» у идей и инсайтов; план на 24 часа, 7 и 30 дней |
| Ход генерации | Статусы шагов, слайды открываются по мере готовности |
| Кэш и ссылка | Повторный запрос открывается сразу; у анализа есть постоянный адрес |

### 3.2. Что не входит и когда появится

| Функция | Когда | Почему не сейчас |
|---|---|---|
| Учётные записи, библиотека, закладки | Версия 1.1 | MVP ценен и без входа |
| Личный план под цели пользователя | 1.1 | Нужен профиль пользователя |
| Загрузка EPUB, PDF, TXT и анализ по полному тексту | 1.2 | Отдельный большой блок: разбор файлов, приватность, хранение |
| Чат, «объясни проще», Deep Dive | 1.2 | Имеют смысл, когда презентация уже хороша |
| Тест, карточки, интеллект-карта | 1.3 | То же |
| Сравнение книг и авторов | 1.4 | Нужна база готовых анализов |
| Интеллектуальный профиль | 1.5 | Нужны учётные записи и история |
| Экспорт в PDF, озвучка | 1.5 | Не влияют на качество анализа |

### 3.3. Состав презентации

| Раздел | Слайдов |
|---|---|
| Обложка | 1 |
| О чём книга | 1 |
| Главные идеи | 1–2 |
| Разбор по главам или тематический разбор | 1–2 |
| Ключевые концепции (по одной на слайд) | 1–3 |
| Самые ценные инсайты | 2–3 |
| Практическое применение | 1–2 |
| Мировоззрение автора | 1 |
| Критический анализ | 1–2 |
| Связь с другими знаниями | 1 |
| Главные выводы | 1 |
| План внедрения | 1 |
| AI-аналитика | 1 |
| **Итого** | **14–20** |

Сумма максимумов даёт 21, поэтому действует предел в 20 слайдов: при превышении сборщик объединяет концепции. Нижняя граница 14 — потому что ни один раздел ТЗ не пропускается.

### 3.4. Ограничение, о котором нужно знать

MVP работает без текста книги — только по открытым источникам. Это слабейший из двух режимов по точности:

- для известных книг источников достаточно, и разбор будет содержательным;
- для малоизвестных книг источников может не хватить — тогда продукт скажет об этом, а не сочинит содержание;
- разбор по главам появляется, только если оглавление подтверждено; иначе — тематический разбор.

Примеры на главной подбираются из книг с хорошим покрытием, чтобы первое впечатление соответствовало реальным возможностям.

### 3.5. Критерии готовности MVP

- На десяти контрольных книгах разных жанров ручная проверка не находит фактических ошибок в утверждениях с меткой «Книга».
- У каждого факта открывается источник; ни одной цитаты без точного совпадения с источником.
- Проверка на специфичность: любой слайд, перенесённый в презентацию другой книги, выглядит там чужим. Слайды, которые подошли бы к любой книге жанра, считаются браком.
- В презентации нет двух слайдов с одной и той же мыслью.
- Каждое действие конкретно: есть объект и срок.
- Презентация удобна на экране шириной 360 px.
- Время и стоимость генерации измерены и записаны; пользователь видит ход работы.
- Нет ни одной кнопки без функции.

### 3.6. Что нужно для MVP

| Что | Нужно в MVP |
|---|---|
| Next.js, TypeScript, Tailwind | да |
| PostgreSQL | да |
| Очередь фоновых задач | да |
| Claude API | да |
| Open Library | да |
| Авторизация, хранилище файлов, Redis, сервис PDF, векторный поиск | нет |

От владельца проекта: ключ Claude API, база данных, хостинг и возможность устанавливать пакеты в рабочей среде.
