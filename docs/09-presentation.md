# Этап 7. Интерактивная презентация

## Состояние

Просмотрщик, карточка источника, страница хода работы и запуск анализа со страницы книги готовы и проверены тестами. **На настоящих данных презентация ещё не показывалась:** движок ([этап 6](08-ai-engine.md)) не запускался на настоящей модели, потому что в проекте нет ключа Claude API. Всё проверено на анализе, который настоящий пайплайн собрал на подставной модели: книга в нём выдуманная и пользователям не показывается.

| Критерий из [плана](04-roadmap.md) | Состояние |
|---|---|
| Все 12 разделов ТЗ отображаются; длинный текст не ломает слайд | Да — на тестовом анализе: 12 разделов и AI-аналитика, отдельный тест с очень длинными словами и заголовками. На реальных данных — после первого прогона |
| У каждого утверждения источник открывается в один клик | Да |
| Презентация удобна на телефоне шириной 360 px | Да: лента карточек, нижняя панель, области нажатия не меньше 44 px |
| Режим анализа виден на каждом экране презентации | Да: закреплён в шапке презентации |

## Путь пользователя

1. **Страница книги** → кнопка «Создать анализ». Если анализ этой книги уже есть — «Открыть анализ», если идёт — «Смотреть ход работы». Если на сервере нет ключа модели, кнопки нет, а страница прямо говорит, что запуск недоступен.
2. **Ход работы** (`/analysis/…`): восемь шагов с состоянием каждого, страница обновляется сама. После поиска источников показывает, сколько их найдено и чего не хватает. Страницу можно закрыть — готовый результат откроется по тому же адресу.
3. **Презентация** — по тому же адресу, когда анализ готов и прошёл проверку.

Исходы, кроме успешного, тоже показаны честно:

| Исход | Что видит пользователь |
|---|---|
| Мало источников | «Анализ не создан: мало источников» и чего именно не хватило. Анализ без проверяемой основы не показывается |
| После проверки фактов осталось слишком мало | «Анализ не прошёл проверку» с причинами |
| Сбой или перезапуск сервера | Что успело выполниться и кнопка «Продолжить анализ» — готовые шаги не повторяются |

## Просмотрщик

- **Большой экран:** список слайдов слева, слайд по центру, внизу — навигация, прогресс, переключатель «Слайды / Чтение» и полный экран. Клавиши ← → Home End PageUp PageDown.
- **Телефон:** все слайды лентой карточек; нижняя панель с номером слайда, стрелками и кнопкой «Слайды», которая открывает список снизу.
- **Адрес слайда:** `#slide-5` — ссылкой на конкретный слайд можно поделиться.
- **Метка происхождения — кнопка.** Открывает карточку: тип утверждения, источники с дословной выдержкой и ссылкой, результат проверки; для выводов AI и критики — утверждения, на которых они построены, с переходом к каждому.
- **«Что с этим делать»** — у идей и инсайтов, с переходом к идее, из которой следует действие.
- **Схемы:** шесть типов — последовательность, цикл, пирамида, матрица, сравнение, структура. Собраны из разметки, а не из картинок, поэтому читаются экранным диктором и перестраиваются на телефоне.
- **AI-аналитика:** шесть оценок с объяснением каждой и пометкой, что это мнение AI, плюс четыре «самые…» идеи.
- **«Как сделан этот анализ»** — по нажатию на режим в шапке: сколько фактов проверено, подтверждено, понижено и удалено, чего не хватило, полный список источников.

## Как это устроено

```
src/analysis/
  service.ts   запуск и продолжение анализа, ход работы, данные для презентации
  types.ts     типы записи об анализе, состояния и данных презентации
src/app/analysis/
  [id]/page.tsx  презентация или ход работы — в зависимости от состояния
  actions.ts     серверные действия «Создать анализ» и «Продолжить»
src/components/presentation/
  presentation.tsx   просмотрщик
  blocks.tsx         блоки слайда: утверждение, элемент, действие, оценка
  diagram.tsx        шесть типов схем
  source-dialog.tsx  карточка источника
```

- **Один анализ на книгу.** Идентификатор вычисляется из книги, режима, языка и версии пайплайна: повторный запрос открывает готовый результат и не тратит токены. Одновременные запросы на одну книгу запускают один анализ.
- **Ограничение нагрузки:** не больше двух анализов одновременно на процесс.
- **Хранение.** С переменной `ANALYSIS_STORE_DIR` результаты пишутся в файлы и переживают перезапуск; без неё — живут в памяти.

## Ограничения

1. **Не проверено на настоящей модели.** Запуск со страницы книги проверен модульными тестами сервиса на подставной модели; вызов настоящего Claude API из приложения ни разу не выполнялся.
2. **Анализ идёт внутри процесса сервера.** Это работает на обычном сервере (`npm run start`). На бессерверном хостинге вроде Vercel запрос живёт ограниченное время, и многоминутный анализ оборвётся — там нужны фоновая очередь и база данных из [архитектуры](03-architecture.md). До их подключения публиковать приложение на таком хостинге нельзя.
3. **Нет входа в аккаунт** (этап 9): запустить анализ может любой, кто откроет страницу. Вместе с пунктом 2 это значит, что открытый доступ к приложению с ключом модели — прямой расход денег. Сейчас от злоупотребления защищают только лимит в два анализа и общий кэш.
4. **Слайды открываются после окончания анализа**, а не по мере готовности: проверка фактов — последний шаг, и до неё показывать утверждения как проверенные нельзя. Во время работы видны шаги и отчёт об источниках.
5. **Блока «Примеры готовых презентаций» на главной пока нет** — его нечем наполнить до первых настоящих анализов.
6. Инструменты (чат, тест, карточки) и экспорт в PDF — этапы 8 и 9; кнопок для них в интерфейсе нет.

## Тесты

- **Модульные** (`tests/unit/analysis-service.test.ts`): путь от запуска до презентации, повторный и одновременный запуск, лимит, остановка за нехваткой источников, сбой и продолжение, прерванный анализ.
- **Сценарные** (`tests/e2e/presentation.spec.ts`): навигация кнопками, клавишами и из списка; все разделы ТЗ; источник в один клик, включая переход от вывода к фактам; действия, схемы, оценки; телефон 360 px; длинные тексты; доступность axe в обеих темах, в том числе с открытой карточкой; страницы прерванного и остановленного анализа.

Тестовый анализ лежит в `tests/fixtures/analysis/` и пересобирается командой `npm run fixtures:analysis` после изменений в пайплайне.

## Что нужно, чтобы увидеть настоящий анализ

1. Ключ Claude API в переменной `ANTHROPIC_API_KEY` (в файле `.env.local`; в репозиторий он не попадает).
2. `ANALYSIS_STORE_DIR=.data/analyses`, чтобы результат не пропал при перезапуске.
3. `npm run build && npm run start`, найти книгу, нажать «Создать анализ».

Первый прогон стоит делать на одной книге и сразу записать время и стоимость в [документ о движке](08-ai-engine.md).
